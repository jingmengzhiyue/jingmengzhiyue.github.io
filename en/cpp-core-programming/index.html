C++ Core Programming

This stage offers a detailed treatment of C++ ==object-oriented== programming techniques, examining the core and essence of the language.

1 Memory Partition Model

When a C++ program runs, memory is broadly divided into 4 regions

  • Code segment: holds the binary code of function bodies and is managed by the operating system
  • Global segment: holds global variables, static variables, and constants
  • Stack segment: automatically allocated and freed by the compiler; it stores function parameters, local variables, and the like
  • Heap segment: allocated and freed by the programmer; if the programmer does not release it, the operating system reclaims it when the program ends

Significance of the four memory regions:

Data kept in different regions is assigned different lifetimes, affording us greater flexibility in programming

1.1 Before the Program Runs

Once the program is compiled, an executable exe file is produced. Before that program is executed, it is divided into two regions

Code segment:

It stores the machine instructions executed by the CPU

The code segment is shared; sharing means that for a frequently run program only a single copy of the code needs to reside in memory

The code segment is read-only, a restriction that keeps the program from accidentally altering its own instructions

Global segment:

Global variables and static variables are stored here.

The global segment also contains the constant area, where string literals and other constants reside.

==Data in this region is released by the operating system once the program ends==.

4 Classes and Objects

The three hallmarks of C++ object-oriented programming are ==encapsulation, inheritance, and polymorphism==

C++ treats ==all things as objects==, and each object has its own attributes and behaviors

For example:

A person can be treated as an object, with attributes such as name, age, height, and weight, and behaviors such as walking, running, jumping, eating, and singing…

A car can likewise be treated as an object, with attributes such as wheels, a steering wheel, and headlights, and behaviors such as carrying passengers, playing music, and running the air conditioner…

==Objects== sharing the same nature can be abstracted into a ==class==: a person belongs to the human class, and a car belongs to the car class

Encapsulation is one of the three hallmarks of C++ object-oriented programming

4.2 Object Initialization and Cleanup

  • Electronic products we buy in daily life generally come with factory settings, and one day, when we no longer use them, we delete personal data to keep it safe
  • Object-oriented programming in C++ comes from life: each object likewise has initial settings along with a data-cleanup step performed just before it is destroyed.

4.2.1 Constructors and Destructors

The initialization and cleanup of objects are two critically important safety concerns

Using an object or variable with no initial state has unpredictable consequences; equally, failing to clean up an object or variable promptly after use can create safety problems

C++ addresses these issues with constructors and destructors, which the compiler invokes automatically to carry out initialization and cleanup.

Object initialization and cleanup are tasks the compiler insists upon, so if we supply neither, the compiler will supply them

The constructor and destructor supplied by the compiler have empty implementations.

  • Constructor: its main role is to assign values to an object’s member attributes at creation time; the compiler calls it automatically, so no manual call is needed.
  • Destructor: the system calls it automatically just before an object is destroyed, to perform cleanup work.

Constructor syntax: ClassName(){}

  1. A constructor has no return value and does not write void
  2. Its name is identical to the class name
  3. A constructor may take parameters and can therefore be overloaded
  4. The constructor is called automatically when an object is created; no manual call is needed, and it runs only once

Destructor syntax: ~ClassName(){}

  1. A destructor has no return value and does not write void
  2. Its name matches the class name, prefixed by the symbol ~
  3. A destructor cannot take parameters and therefore cannot be overloaded
  4. The destructor is called automatically just before an object is destroyed; no manual call is needed, and it runs only once

	{
		// Start the parts by calling their interfaces
		m_cpu->calculate();

		m_vc->display();

		m_mem->storage();
	}

	// Destructor that releases the three parts
	~Computer()
	{

		// Release the CPU
		if (m_cpu != NULL)
		{
			delete m_cpu;
			m_cpu = NULL;
		}

		// Release the graphics card
		if (m_vc != NULL)
		{
			delete m_vc;
			m_vc = NULL;
		}

		// Release the memory module
		if (m_mem != NULL)
		{
			delete m_mem;
			m_mem = NULL;
		}
	}

private:

	CPU * m_cpu; // Pointer to the CPU part
	VideoCard * m_vc; // Pointer to the graphics card part
	Memory * m_mem; // Pointer to the memory module part
};

5 File Operations

Data generated while a program runs is temporary and is released once the program ends

Files, by contrast, let data persist

File operations in C++ require including the header ==< fstream >==

There are two kinds of file:

  1. Text file - the file is stored in the computer in ASCII form
  2. Binary file - the file is stored in the computer in binary form, which users normally cannot read directly

Three classes handle file operations:

  1. ofstream: writing
  2. ifstream: reading
  3. fstream : reading and writing

5.1 Text Files

5.1.1 Writing Files

The steps for writing a file are as follows:

  1. Include the header file

    #include <fstream>

  2. Create a stream object

    ofstream ofs;

  3. Open the file

    ofs.open(“file_path”, open_mode);

  4. Write the data

    ofs « “data to write”;

  5. Close the file

    ofs.close();
