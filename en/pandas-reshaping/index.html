I. Reshaping Long and Wide Tables

What is a long table, and what is a wide table? The distinction is made with respect to a particular feature. If a table stores gender in one column, it is a long table with respect to gender; if gender is used as the column names and the cells hold values of some other related feature, the table is a wide table with respect to gender. The two tables below are, respectively, long and wide tables with respect to gender:

1

pd.DataFrame({'Gender':['F','F','M','M'], 'Height':[163, 160, 175, 180]})

GenderHeight
0F163
1F160
2M175
3M180
1

pd.DataFrame({'Height: F':[163, 160], 'Height: M':[175, 180]})

Height: FHeight: M
0163175
1160180

Clearly the two tables carry exactly the same information - the same height figures - presented in different ways. That presentation depends chiefly on the layout chosen for the gender column: is it stored in the $\color{red}{\text{long}}$ form or the $\color{red}{\text{wide}}$ form? Accordingly, pandas provides a number of reshaping functions for this kind of long/wide conversion.

1. pivot

pivot is a typical function for turning a long table into a wide one. Consider the following example: the table stores the Chinese and math scores of San Zhang and Si Li, and we want those two subjects to appear as columns.

1
2
3
4
5

df = pd.DataFrame({'Class':[1,1,2,2],
                   'Name':['San Zhang','San Zhang','Si Li','Si Li'],
                   'Subject':['Chinese','Math','Chinese','Math'],
                   'Grade':[80,75,90,85]})
df

ClassNameSubjectGrade
01San ZhangChinese80
11San ZhangMath75
22Si LiChinese90
32Si LiMath85

For a basic long-to-wide operation, three elements matter most: the row index of the reshaped table, the columns to be moved into the column index, and the values associated with those columns and rows. These correspond to the index, columns, and values parameters of pivot. The column index of the new table is the unique values of the columns columns, its row index is the unique values of the index columns, and values identifies the column holding the numbers to display.

1

df.pivot(index='Name', columns='Subject', values='Grade')

SubjectChineseMath
Name
San Zhang8075
Si Li9085

The color coding makes the reshaping process easier to follow:

Using pivot requires a uniqueness condition: since each row-column pair in the new table maps to a single value, the row combinations of the index and columns columns in the original table must be unique. For example, changing San Zhang’s math score in the second row to Chinese would raise an error, because the pair ("San Zhang", "Chinese") would then occur twice for Name and Subject, leaving it unclear whether the reshaped cell should contain 80 or 75.

1
2
3
4
5
6

df.loc[1, 'Subject'] = 'Chinese'
try:
    df.pivot(index='Name', columns='Subject', values='Grade')
except Exception as e:
    Err_Msg = e

2. pivot_table

pivot relies on the uniqueness condition. When that condition fails, aggregation must collapse the multiple values sharing a row-column combination into one. Suppose San Zhang and Si Li each took two Chinese exams and two math exams, and the school’s rules make the final grade the average of the two scores; pivot alone cannot produce this result.

1
2
3
4
5
6
7

df = pd.DataFrame({'Name':['San Zhang', 'San Zhang', 
                              'San Zhang', 'San Zhang',
                              'Si Li', 'Si Li', 'Si Li', 'Si Li'],
                   'Subject':['Chinese', 'Chinese', 'Math', 'Math',
                                 'Chinese', 'Chinese', 'Math', 'Math'],
                   'Grade':[80, 90, 100, 90, 70, 80, 85, 95]})
df

NameSubjectGrade
0San ZhangChinese80
1San ZhangChinese90
2San ZhangMath100

pandas provides pivot_table for this purpose, where the aggfunc parameter is the aggregation function to use. The scenario above can be written as follows:

1
2
3
4

df.pivot_table(index = 'Name',
               columns = 'Subject',
               values = 'Grade',
               aggfunc = 'mean')

SubjectChineseMath
Name
San Zhang8595
Si Li7590

The aggfunc argument accepts all the valid aggregation strings introduced in the previous chapter. You may also supply a custom function that takes a series and returns a scalar, which gives the same result equivalently:

1
2
3
4

df.pivot_table(index = 'Name',
               columns = 'Subject',
               values = 'Grade',
               aggfunc = lambda x:x.mean())

SubjectChineseMath
Name
San Zhang8595
Si Li7590

In addition, pivot_table can compute marginal summaries by setting margins=True; the aggregation applied at the margins matches the method given in aggfunc. The following table reports the mean Chinese and math scores, the mean scores of San Zhang and of Si Li, and the overall mean of all four scores:

1
2
3
4
5

df.pivot_table(index = 'Name',
               columns = 'Subject',
               values = 'Grade',
               aggfunc='mean',
               margins=True)

SubjectChineseMathAll
Name
San Zhang8595.090.00
Si Li7590.082.50
All8092.586.25

In the marginal-summary example above, a row or column summary is the average of the corresponding row or column entries in the new table, while the grand total is the average of all four entries. Must this relationship always hold? If not, give an example to show why.

3. melt

Long and wide tables differ only in presentation, not in the information they contain. Having used pivot to turn a long table into a wide one, we can reverse the operation to turn a wide table back into a long one; that is what melt does. In the example below, Subject is stored in the column index, and we want to compress it into a single column.

4. wide_to_long

In melt, the column elements compressed into one column can only represent a single level of meaning, namely values_name. If the column labels encode crossed categories - say midterm versus final and Chinese versus math - you may want to expand the Grade corresponding to values_name into two columns, one for Chinese scores and one for math scores, compressing only the midterm/final information. That is when wide_to_long is needed.

II. Reshaping Indexes

1. stack and unstack

Chapter 2 introduced swapping levels within an index using swaplevel or reorder_levels. What follows concerns exchanges $\color{red}{\text{between row and column indexes}}$ - that is, between the row and column indexes. Because such an exchange changes the dimensions of the DataFrame, it is a reshaping operation. The four reshaping functions in the first section differ in that they convert $\color{red}{\text{elements}}$ of one or more columns and the $\color{red}{\text{column indexes}}$ into each other, rather than converting indexes into one another.

unstack moves a row index level into the column index, as in this simple example:

2. The Relationship Between Aggregation and Reshaping

Of all the functions described above, every one except pivot_table, which aggregates, leaves the number of values unchanged before and after reshaping; only their presentation changes. The group-aggregation operation from the previous chapter necessarily counts as a special kind of reshaping, since it creates new row and column indexes, but aggregation collapses several original values into one and therefore changes the number of values. That is the essential difference between grouped aggregation and the reshaping functions.

III. Other Reshaping Functions

1. crosstab

crosstab occupies an awkward position, since everything it can do can also be done with pivot_table. By default it counts how often combinations of elements occur - a count operation. For example, to count the frequency of each school and transfer-status combination in the learn_pandas dataset:

1
2

df = pd.read_csv('../data/learn_pandas.csv')
pd.crosstab(index = df.School, columns = df.Transfer)

TransferNY
School
Fudan University381
Peking University282
Shanghai Jiao Tong University530
Tsinghua University624

This is equivalent to the following way of writing crosstab, where aggfunc is the aggregation parameter:

1

pd.crosstab(index = df.School, columns = df.Transfer, values = [0]*df.shape[0], aggfunc = 'count')

TransferNY
School
Fudan University38.01.0
Peking University28.02.0
Shanghai Jiao Tong University53.0NaN
Tsinghua University62.04.0

An equivalent result can also be obtained with pivot_table. Since we are counting combinations here, whichever column is passed to values has no effect on the outcome:

1
2
3
4

df.pivot_table(index = 'School',
               columns = 'Transfer',
               values = 'Name',
               aggfunc = 'count')

TransferNY
School
Fudan University38.01.0
Peking University28.02.0
Shanghai Jiao Tong University53.0NaN
Tsinghua University62.04.0

The difference between the two functions is now clear: crosstab receives an actual series in that position, whereas pivot_table receives the name of a column in the calling table; passing a series to pivot_table raises an error.

Beyond the default count, all aggregation strings and custom functions returning a scalar are available. For instance, to compute the mean height for each combination:

1

pd.crosstab(index = df.School, columns = df.Transfer, values = df.Height, aggfunc = 'mean')

TransferNY
School
Fudan University162.043750177.20
Peking University163.429630162.40
Shanghai Jiao Tong University163.953846NaN
Tsinghua University163.253571164.55
