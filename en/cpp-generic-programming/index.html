1.2 Function Templates

  • Another programming paradigm in C++ is known as ==generic programming==, and the technique it chiefly relies on is the template.
  • C++ offers two template mechanisms: function templates and class templates.

// Selection sort that orders the array from largest to smallest
void mySort(T arr[], int len)
{
	for (int i = 0; i < len; i++)
	{
		int max = i; // Index of the largest element
		for (int j = i + 1; j < len; j++)
		{
			if (arr[max] < arr[j])
			{
				max = j;
			}

		}
	}

1.2.5 Calling Rules for Ordinary Functions and Function Templates

The calling rules are as follows:

  1. When both a function template and an ordinary function can do the job, the ordinary function is preferred.
  2. A function template can be forced by supplying an empty template argument list.
  3. Function templates may also be overloaded.
  4. When a function template yields a better match, it is called in preference.

	cout << "Calling the overloaded template" << endl; 
}

void test01()
{
	// 1. If both the function template and the ordinary function can match, the ordinary function is preferred
	// Note: if you tell the compiler the ordinary function exists but only declare it, or define it in another file, the compiler reports that it cannot find it
	int a = 10;
	int b = 20;
	myPrint(a, b); // Calls the ordinary function

	// 2. An empty template argument list forces the function template to be called
	myPrint<>(a, b); // Calls the function template

	// 3. Function templates can also be overloaded
	int c = 30;
	myPrint(a, b, c); // Calls the overloaded function template

	// 4. If the function template produces a better match, it is preferred
	char c1 = 'a';
	char c2 = 'b';
	myPrint(c1, c2); // Calls the function template
}

int main() {

	test01();

	system("pause");

	return 0;
}

Summary: Since function templates are available, it is best to avoid providing an ordinary function as well, for ambiguity may easily arise.

#include <string>

class Person
{

	Person(string name, int age)

	int m_Age;

// Ordinary function template
template<class T>
bool myCompare(T& a, T& b)
{
	if (a == b)
	{
		return true;
	}
	else
	{
		return false;
	}
}


// Specialization: the explicit specialization prototype and definition start with template<> and name the type
// A specialization is preferred over the generic template
template<> bool myCompare(Person &p1, Person &p2)
{
	if ( p1.m_Name  == p2.m_Name && p1.m_Age == p2.m_Age)
	{
		return true;
	}
	else
	{
		return false;
	}
}

void test01()
{
	int a = 10;
	int b = 20;
	// Built-in types can use the generic function template directly
	bool ret = myCompare(a, b);
	if (ret)
	{
		cout << "a == b " << endl;
	}
	else
	{
		cout << "a != b " << endl;
	}
}

void test02()
{
	Person p1("Tom", 10);
	Person p2("Tom", 10);
	// User-defined types do not use the generic function template
	// A specialization for the Person type can be created to handle this type specially
	bool ret = myCompare(p1, p2);
	if (ret)
	{
		cout << "p1 == p2 " << endl;
	}
	else
	{
		cout << "p1 != p2 " << endl;
	}
}

int main() {

	test01();

	test02();

	system("pause");

	return 0;
}

Summary:

  • Specialized templates can resolve the generalization of user-defined types.
  • The point of learning templates is less about writing them yourself and more about applying the templates supplied by the STL.

2 A First Look at the STL

2.1 The Birth of the STL

  • For a long time, the software community has wanted to create something reusable.
  • The object-oriented and generic programming ideas in C++ aim at improving reusability.
  • More often than not, data structures and algorithms lacked a common standard, forcing people into a great deal of repetitive work.
  • To establish a standard for data structures and algorithms, the STL came into being.

2.2 Basic STL Concepts

  • STL (Standard Template Library, standard template library)
  • Broadly speaking, the STL is divided into: containers, algorithms, and iterators.
  • Containers and algorithms are seamlessly connected through iterators.
  • Almost all STL code takes the form of template classes or template functions.

2.3 The Six Components of the STL

The STL is broadly divided into six components: containers, algorithms, iterators, functors, adapters, and allocators.

  1. Containers: the various data structures—such as vector, list, deque, set, and map—used to store data.
  2. Algorithms: the various common algorithms, such as sort, find, copy, and for_each.
  3. Iterators: these act as the glue between containers and algorithms.
  4. Functors: entities that behave like functions and can serve as a strategy for an algorithm.
  5. Adapters: things used to modify the interface of a container, functor, or iterator.
  6. Allocators: responsible for the allocation and management of memory space.

2.4 Containers, Algorithms, and Iterators in the STL

Container: a place to put things.

An STL container is an implementation of the most widely used data structures.

Common data structures include arrays, linked lists, trees, stacks, queues, sets, and maps.

These containers fall into two categories: sequence containers and associative containers.

Sequence containers emphasize the ordering of values; every element in a sequence container has a fixed position. Associative containers are binary-tree structures in which elements have no strict physical ordering relative to one another.

Algorithm: a solution to a problem.

A finite sequence of steps that resolves a logical or mathematical problem is what we call an algorithm.

Algorithms are divided into mutating algorithms and non-mutating algorithms.

A mutating algorithm changes the contents of the elements in a range during the operation—copying, replacing, deleting, and so on.

A non-mutating algorithm leaves the contents of the elements unchanged during the operation—searching, counting, traversing, finding extrema, and so on.

Iterator: the glue between containers and algorithms.

It provides a way to visit the elements of a container in sequence without exposing the container’s internal representation.

Every container has its own dedicated iterator.

Using an iterator is very much like using a pointer; at the outset, you can simply think of an iterator as a pointer.

Iterator categories:

CategoryFunctionSupported Operations
Input iteratorRead-only access to dataRead-only; supports ++, ==, !=
Output iteratorWrite-only access to dataWrite-only; supports ++
Forward iteratorRead and write operations, able to advance the iteratorRead/write; supports ++, ==, !=
Bidirectional iteratorRead/write operations, able to move forward and backwardRead/write; supports ++, –
Random-access iteratorRead/write operations, able to access any element by jumping; the most powerful iteratorRead/write; supports ++, –, [n], -n, <, <=, >, >=

The iterator types most commonly used in containers are the bidirectional iterator and the random-access iterator.

Function:

3.3 The deque Container

3.3.1 Basic deque Concepts

Function:

  • A double-ended array that supports insertion and deletion at the front end.

The difference between deque and vector:

  • vector is inefficient at inserting and deleting at the front, and the larger the data set, the lower the efficiency.
  • deque, by comparison, inserts and deletes at the front faster than vector.
  • vector accesses elements faster than deque, a consequence of their different internal implementations.

How deque works internally:

Inside a deque there is a central controller that maintains the contents of each buffer, and the buffers hold the actual data.

What the central controller maintains is the address of each buffer, so that using a deque feels like using a single contiguous block of memory.

  • The iterator of a deque container also supports random access.

3.7 The list Container

3.7.1 Basic list Concepts

Function: store data in linked fashion.

A linked list (list) is a storage structure whose physical units are non-contiguous; the logical order of the data elements is realized through the links of pointers in the list.

A list consists of a series of nodes.

A node consists of a data field, which stores the data element, and a pointer field, which stores the address of the next node.

The list in the STL is a doubly linked circular list.

Because a list’s storage is not a contiguous block of memory, its iterators support only forward and backward movement; they are bidirectional iterators.

Advantages of list:

  • It uses dynamic memory allocation, so it causes no memory waste or overflow.
  • Insertion and deletion are very convenient—just modify pointers, with no need to move large numbers of elements.

Disadvantages of list:

  • Although a list is flexible, it pays a considerable extra cost in space (the pointer fields) and time (traversal).

An important property of list is that insertions and deletions never invalidate existing list iterators, which does not hold for vector.

Summary: In the STL, list and vector are the two most commonly used containers, each with its own strengths and weaknesses.
