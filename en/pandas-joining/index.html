Pandas Joining

1
2

import numpy as np
import pandas as pd

I. Relational Joins

1. Basic Concepts of Joins

Joining two related tables on one key or a set of keys is a common operation. For example, the score sheets for the various subjects of a student’s final exam can be joined on $\color{red}{\text{name}}$ and $\color{red}{\text{class}}$ into a single grade report; likewise, the various information tables of a company’s employees can be joined and summarized by $\color{red}{\text{employee ID}}$. As these examples show, in a relational join the $\color{red}{\text{key}}$ is of central importance and is usually specified with the on parameter.

Another essential element is the form of the join. In pandas, the relational join functions merge and join offer a how parameter that represents the join form: left join left, right join right, inner join inner, and outer join outer. Their differences are illustrated in the following diagram:

As the figure shows, a left join takes the keys of the left table as authoritative: if a key from the right table also exists in the left table, it is added to the left table; otherwise it is treated as a missing value. A right join is handled analogously. An inner join concerns itself only with keys that appear on both sides, whereas an outer join builds on the inner join by also including values present only on the left or only on the right — which is why the outer join is also called a full join.

In the simple example above, no key is repeated within a single table. What happens, then, when a key does repeat? A single rule covers it: any value appearing on both sides is combined by way of a Cartesian product, while a value appearing on only one side is handled according to the join form. The Cartesian product can be explained with a small example: suppose the key San Zhang occurs twice in the left table and twice in the right table. Matching the rows one by one produces a table that necessarily contains 2*2 rows with the name San Zhang. The diagram below shows a corresponding case:

Different circumstances call for different join forms. Left and right joins are equivalent to each other; since the keys in their results are determined by one of the tables, they are often used to add information directionally to a target table. With inner and outer joins the two tables usually stand on an equal footing — swapping the left and right tables leaves the result unchanged — and the aim is to extract the intersection or the union of the keys. Which one to choose ultimately depends on the needs of the task at hand.

2. Value-Based Joins

In the illustrated example above, the two tables are joined on the values of one column. In fact, a join can also be based on a combination of several columns. Such value-based joins are implemented in pandas by the merge function; take the left join from the first figure, for instance:

df1 = pd.DataFrame({'Name':['San Zhang','Si Li'], 'Age':[20,30]})
df2 = pd.DataFrame({'Name':['Si Li','Wu Wang'], 'Gender':['F','M']})
df1.merge(df2, on='Name', how='left')

The examples above show that a join relying on uniqueness breaks down when the keys are not unique. The example has only a handful of rows, but real data may involve hundreds of thousands or even millions of rows; to guarantee uniqueness there, besides checking for duplicates with duplicated, merge also offers a validate parameter that checks the uniqueness mode of the join. Three modes are available: one-to-one 1:1, one-to-many 1:m, and many-to-one m:1. The first means the keys are unique in both tables; the latter two mean the keys are unique in the left table and in the right table, respectively.

3. Index Joins

An index join treats the index as the key, so in essence it is no different from a value join. In pandas, index joins are handled by the join function, which takes fewer options than merge. Apart from the mandatory on and how, you may specify left and right suffixes — lsuffix and rsuffix — for overlapping columns. Here on refers to the index name; with a single-level index, omitting the argument means joining on the current index.

1
2
3

df1 = pd.DataFrame({'Age':[20,30]}, index=pd.Series(['San Zhang','Si Li'],name='Name'))
df2 = pd.DataFrame({'Gender':['F','M']}, index=pd.Series(['Si Li','Wu Wang'],name='Name'))
df1.join(df2, how='left')

II. Directional Joins

1. concat

The previous section introduced relational joins, whose most important parameters are on and how. Sometimes, however, the user does not care which column serves as the key and simply wants to concatenate two or more tables vertically or horizontally. pandas provides the concat function for precisely this need.

In concat, three parameters are used most often: axis, join, keys. They denote, respectively, the direction of concatenation, the join form, and the names that indicate in the new table which old table each row came from. Note carefully that join and keys here have nothing to do with the join function and the notion of keys discussed earlier.

By default axis=0, which concatenates several tables vertically and is commonly used to stack multiple samples; axis=1 concatenates them horizontally and is typically used to combine multiple fields or features.

For example, vertically combine the person records from several tables:

1
2
3

df1 = pd.DataFrame({'Name':['San Zhang','Si Li'], 'Age':[20,30]})
df2 = pd.DataFrame({'Name':['Wu Wang'], 'Age':[40]})
pd.concat([df1, df2])

NameAge
0San Zhang20
1Si Li30
0Wu Wang40

Horizontally combine the fields from several tables:

1
2
3

df2 = pd.DataFrame({'Grade':[80, 90]})
df3 = pd.DataFrame({'Gender':['M', 'F']})
pd.concat([df1, df2, df3], 1)

NameAgeGradeGender
0San Zhang2080M
1Si Li3090F

Although concat is a function for relational-style combining, it still joins on indexes. Vertical concatenation aligns on the column index: by default join=outer, which keeps all columns and sets absent values to missing, whereas join=inner keeps only the columns that appear in both tables. Horizontal concatenation aligns on the row index, with the join parameter set in much the same way.

1
2

df2 = pd.DataFrame({'Name':['Wu Wang'], 'Gender':['M']})
pd.concat([df1, df2])

Therefore, once you have decided on a direct, multi-table concatenation — especially a horizontal one — it is wise to call reset_index first to restore the default integer index. Doing so prevents the erroneous results caused by misaligned indexes and by the Cartesian product of duplicate indexes.

Finally, keys is useful in situations where several tables have been combined and you still want to know which original table each row of the new table came from. Passing keys creates a multi-level index that labels the source. For instance, if the first table holds students from Class One and the second holds students from Class Two, you can combine them as follows:

1
2

df1 = pd.DataFrame({'Name':['San Zhang','Si Li'], 'Age':[20,21]})
df2 = pd.DataFrame({'Name':['Wu Wang'],'Age':[21]})
pd.concat([df1, df2], keys=['one', 'two'])

2. Combining Series with Tables

concat allows directional concatenation among several tables. To append a single Series to the end of the rows or the end of the columns of a table, use append and assign, respectively.

In append, if the original table uses the default integer index, ignore_index=True labels the index of the new Series automatically; otherwise you must give the Series a name attribute.

1
2

s = pd.Series(['Wu Wang', 21], index = df1.columns)
df1.append(s, ignore_index=True)

0San Zhang20
1Si Li21
2Wu Wang21

As for assign, although it can add a new column, the same effect is usually achieved with df['new_col'] = .... The drawback of using [] is that it modifies the original table in place, whereas assign returns a temporary copy:

s = pd.Series([80, 90])
df1.assign(Grade=s)

III. Join-Like Operations

Besides the join functions described above, pandas also provides several functions that carry out certain operations on two tables. Here they are grouped together under the name join-like operations.

1. Comparison

compare is a new function introduced in version 1.1.0. It compares two tables or two Series and summarizes their differences:

1
2
3
4
5
6
7

df1 = pd.DataFrame({'Name':['San Zhang', 'Si Li', 'Wu Wang'],
                    'Age':[20, 21 ,21],
                    'Class':['one', 'two', 'three']})
df2 = pd.DataFrame({'Name':['San Zhang', 'Li Si', 'Wu Wang'],
                    'Age':[20, 21 ,21],
                    'Class':['one', 'two', 'Three']})
df1.compare(df2)

NameClass
selfotherselfother
1Si LiLi SiNaNNaN
2NaNNaNthreeThree

The result reports the rows and columns where the values differ; positions that are the same are filled with the missing value NaN. Here other and self refer to the argument table passed in and to the calling table itself, respectively.

To display the comparison of every element in the tables in full, set keep_shape=True:

df1.compare(df2, keep_shape=True)

2. Combination

The combine function combines two tables according to a rule you supply, automatically aligning column indexes when it compares them. For the function passed in, the argument at each step is a pair of same-named Series taken from the two tables, and the columns are visited in the order of the union of their names. The example below therefore passes four groups of series, A,B,C,D, each group holding one series from the left table and one from the right. While column A is being compared, s2 denotes an entirely empty series, because that column does not exist in the called table; in addition, the index of the series from the first table is reindexed to the union of the two indexes. You can inspect the whole process by inserting suitable print statements into the function you pass in.

The following example selects the smaller element at each corresponding index position:

1
2
3
4
5
6
7
8

def choose_min(s1, s2):
    s2 = s2.reindex_like(s1)
    res = s1.where(s1<s2, s2)
    res = res.mask(s1.isna()) # # isna returns a Boolean Series marking missing values
    return res
df1 = pd.DataFrame({'A':[1,2], 'B':[3,4], 'C':[5,6]})
df2 = pd.DataFrame({'B':[5,6], 'C':[7,8], 'D':[9,10]}, index=[1,2])
df1.combine(df2, choose_min)
